Documentation & Setup

Complete guide for configuring the qbit-doctarr ecosystem.

qbit-doctarr is a lightweight maintenance suite designed to fix the blind spots in the standard *arr and qBittorrent ecosystem. It does not replace Sonarr/Radarr, nor does it manage your active queue like a master controller. Instead, it acts as a janitor, focusing on metadata cleanup, stalled torrent remediation, malicious file detection, and polite missing media searches.

The Golden Rule: Let qBittorrent handle the active queue. Let the *Arrs handle the imports. Let qbit-doctarr handle the cleanup of things that fall through the cracks.
Credits & Inspiration

This project stands on the shoulders of giants in the *arr community. Specific features were heavily inspired by two fantastic open-source projects:

  • Missing Media Search: Inspired by Houndarr. The "Polite Mode" batching, cooldown limits, and per-item search logic are a direct homage to Houndarr's elegant indexer-safe approach.
  • Unmonitor Downloaded Items: Inspired by Maintainerr. The concept of sweeping your library to unmonitor items that have successfully imported comes from Maintainerr's excellent collection-management philosophy.

qbit-doctarr simply aims to bring those specific capabilities (plus some cleanup tasks) into a single, lightweight Docker container. Huge thanks to the developers of those projects for the inspiration.

qBittorrent, qbit-doctarr, and every *arr instance must run with the same PUID and PGID. This is not optional — it is the single most common cause of "the task found orphans but couldn't do anything about them" failures.

Why this matters

qbit-doctarr performs these operations against directories owned by other containers:

  • Moves orphaned .torrent files out of /downloads/torrent_files into /downloads/quarantine. That requires write permission on the source directory to unlink() the original.
  • Reads qBittorrent's internal BT_backup directory to inventory .torrent/.fastresume pairs.
  • Pauses and deletes torrents via the qBittorrent API — no file access, but the qBittorrent WebUI credentials matter here.
What goes wrong if PUIDs differ

If qBittorrent runs as 1000:1000 and qbit-doctarr runs as 1000:100, then qbit-doctarr sees the .torrent files but cannot delete them from qBittorrent's folders — the operating system returns Permission denied. The task completes, logs "Quarantined 0 files", and moves on. Silent failure.

Worse: qBittorrent's own .torrent copy feature may stop writing to those folders if qbit-doctarr has previously changed their ownership. This is why qbit-doctarr never recursively chowns any directory owned by qBittorrent — the /config and /downloads/quarantine directories are the only ones it manages, and only because they are empty on first boot.

Recommended values

The correct PUID/PGID is whatever your host user actually is. Check on the NAS with:

id
# Example output: uid=1000(youruser) gid=1000(youruser) groups=1000(youruser),100(users)

On most Linux distributions this is 1000:1000. Some NAS systems (Synology, Unraid) use unconventional GIDs — for example, Synology's users group is GID 100. Use whatever the target folder is actually owned by.

Check every container. The common failure mode is that qBittorrent was set up first with the correct PUID/PGID, but qbit-doctarr or an *arr was added later with a copy-pasted PUID=1000 PGID=1000 that doesn't match. All three (qbit-doctarr, qBittorrent, and each *arr) must agree.

Go to Options → BitTorrent in qBittorrent:

  • Torrent Queuing: Keep this enabled. It prevents qBittorrent from choking on 100 active downloads at once.
  • Do not count slow torrents in these limits: Highly Recommended. If a torrent drops below the speed threshold (e.g., 2 KiB/s) for the inactivity timer (e.g., 3600s), qBittorrent will pause it and start a different torrent in the queue.
  • Seeding Limits: Ensure these are configured (e.g., ratio 1.0 or max seeding time). qbit-doctarr relies on the *arrs and qBittorrent to handle the standard seeding lifecycle. When qBittorrent pauses a torrent at 100%, the *arr imports it and removes it.
The "Force Start" Problem

In qBittorrent, clicking Force Start tells the client to ignore all queueing rules, ratio rules, and stall detection. It forces the torrent to run indefinitely.

If you set your *Arrs to use "Force Started" as the Initial State (see the next section), you get faster grab times. However, if a force-started torrent dies (0 B/s), qBittorrent will never mark it as stalled, and the *arr will wait forever.

This is exactly what qbit-doctarr solves. Our Stalled Tracker intentionally bypasses qBittorrent's status and monitors actual data transfer. If a Force-Started torrent stalls, qbit-doctarr will catch it, delete it, and trigger a new search in the *arr.
The Force Start Lifecycle (Important)

If you use Force Start in your *arrs, you must tell qBittorrent to turn it off once the download finishes. If you don't, the torrent will remain force-started, ignore your seeding limits, and clog the queue.

Go to Options → Downloads in qBittorrent and scroll to the bottom:

  1. Check Run external program.
  2. In the Run on torrent finished field, paste the following command:
curl -s -X POST --data "hashes=%I&value=false" "http://localhost:8080/api/v2/torrents/setForceStart"
Note on the command: This tells qBittorrent to call its own API and set the Force Start flag to false the moment a torrent hits 100%. If you access qBittorrent via a different port or IP, adjust localhost:8080 accordingly.

Go to Settings → Download Clients in your *Arr and edit your qBittorrent entry:

  • Category: Ensure this is set (e.g., servarr-radarr). This is mandatory. The *arr will automatically create this category in qBittorrent. qbit-doctarr uses this category to map a torrent back to the correct *arr instance.
  • Post-Import Category: Do NOT use this field. Leave it completely blank. If you change the category after import, qbit-doctarr will lose track of the torrent and its API mapping will break, preventing automated cleanup.
  • Initial State: Force Started (Optional but Recommended). By forcing the start, you bypass qBittorrent's slow queueing logic and grab files immediately. As noted above, qbit-doctarr is designed to catch these if they die.
Remember to add the URL, API Key, and Category exactly as they appear here into the *Arr Instances section of qbit-doctarr's Settings page. If you use Whisparr v3 (Radarr-based) or v2 (Sonarr-based), make sure to set the "Lineage" dropdown correctly in Settings.

The Dashboard is your landing page. It provides a high-level summary of every automated task, showing you:

  • Last Run Status: Success, Error, or Never run.
  • Last Run Details: A brief snippet of what the task actually did.
  • Task-Specific Stats: Database health statuses, for example.
  • Live Countdown: Exactly how long until the next scheduled run.

Clicking any card's title will take you directly to the relevant page or setting. You can also click Refresh Now to force an update without waiting for the 60-second auto-refresh.

If you want to declutter your view, click Customize in the top right. This opens a modal where you can toggle specific cards on or off. Your preferences are saved automatically.

This page is dedicated to the Stalled Tracker. It shows you exactly which torrents are currently being monitored and how much time is left before the script intervenes.

Category Filter: The Stalled Tracker will only ever evaluate torrents that have a category matching one of your enabled *arrs. Manual downloads, games, or other torrents without an *arr category are completely ignored.
Understanding the Statuses
  • meta_stall The torrent is stuck fetching the metadata (magnet link isn't connecting to peers).
  • dl_stall The torrent is downloading, but the speed is below your threshold (or at 0 B/s).
  • seed_stall The torrent is 100% complete but uploading at 0 B/s (only shown if "Pause Completed Stalled Seeds" is enabled).
Features
  • Search & Filter: You can filter by torrent name and use the dropdown to isolate a specific stall type.
  • Sort: Click the column headers to sort the list.
  • Blocklist & Re-search: Deletes the torrent from qBittorrent, adds the release to the *arr blocklist, and triggers a fresh search. (Essentially the same action as the Missing Media page).
  • Run Check Now: Bypasses the scheduler and immediately triggers the Stalled Tracker.

This page tracks items that your *arr is looking for but hasn't successfully downloaded yet. It acts as a polite search scheduler.

Polite vs. Brute Force
  • Polite Mode (Enabled): qbit-doctarr fetches the missing list, tracks items in its database, and searches a small batch every run. It applies a 24-hour cooldown to each item so you don't spam indexers.
  • Polite Mode (Disabled): qbit-doctarr ignores the batch system and tells the *arr to run a full "Search All Missing" command. The *arr handles everything internally.
Tracking Actions
  • Retry: Resets the cooldown and attempt counter for this item.
  • Ignore: Stops qbit-doctarr from searching for this item (it stays in your *arr's wanted list).
  • Blocklist & Re-search: Tells your *arr to blocklist the failed release and immediately triggers a fresh search.
Note on Pruning: If an item is successfully downloaded, it vanishes from your *arr's "Missing" list. The scheduled Missing Media Prune task cleans these "zombie" rows out of qbit-doctarr automatically.

This page houses the manual cleanup tasks. You can run any of these tasks manually at any time.

Scan vs. Action Buttons
  • Scan (Dry Run): This runs the logic and reports what it would do in the "Scan Results" window, but it does not delete, move, or unmonitor anything. Use this to preview actions.
  • Action Buttons: The right-hand button on each card executes the task. The label tells you exactly what will happen (e.g., Quarantine for metadata, Delete for unmanaged torrents, Block for malicious files, Unmonitor for downloaded items, and Search for Missing Media).
The Tasks
  • BT_Backup Repair: Scans qBittorrent's internal folder for orphaned .torrent and .fastresume files.
  • Unmonitor Items: Sweeps your enabled *arrs and unmonitors any items that have successfully downloaded a file. (Helpful for stopping upgrade loops).
  • Unmanaged Torrents: Deletes stopped/paused torrents that no *arr is currently tracking.
  • Malicious Scanner: Reads file lists and blocks torrents containing executables or other dangerous files.
  • Missing Media: Triggers the polite search batch across all enabled *arrs.
  • Quarantine Cleanup: Deletes files in the quarantine folder that are older than the retention limit set in Settings.
Database Maintenance (New)

The blue Database Maintenance card allows you to manually reset the internal tracking tables.

  • Reset Missing: Clears the missing_media table. Use this if you want to force a fresh scan of missing items. The next time the Missing Media task runs, it will re-discover everything from scratch.
  • Reset Stalled: Clears the stalled_torrents table. Use this to reset the timers on all currently stalled torrents, or to clean up if you manually deleted a torrent from qBittorrent.
  • Vacuum DB: Runs a SQLite VACUUM command. This compacts the database file and reclaims storage space, especially after you've deleted a lot of rows. It is safe to run at any time.
Warning: Resetting a table cannot be undone. It clears all historical tracking data for that specific feature. You will be asked for confirmation before the action runs.
The Bottom Panels
  • Scan Results: A live output window showing exactly what the script found or did during the most recent run.
  • Quarantine Manager: Shows all files that have been moved to the Quarantine folder. You can search them, or select and permanently delete them to free up space. Files older than the "Retention" setting (configured in Settings) will be automatically deleted by the scheduled Quarantine Cleanup task.

This page visualizes historical data over time. The system automatically takes an hourly snapshot of your counts and retains it for 30 days.

The Charts
  • Missing Media Sync: Tracks Active, Failed, and Ignored items.
  • Torrent Cleanup: Tracks DL Stall, Meta Stall, and Seed Stall torrents.
Controls
  • 24h / 7d / 30d: Switch the view between the last 24 hours (hourly bars), last 7 days (hourly bars), and last 30 days (daily aggregated bars).
  • Snapshot Now: Forces an immediate snapshot without waiting for the top of the hour. Useful for testing.
Note on 30-day view: Because displaying 720 hourly bars on a screen is unreadable, the 30-day view aggregates the data and shows the last snapshot of each day.

Automation Schedules

Located in the Settings page, these allow you to configure how often the background scheduler runs each task.

  • Enable Toggle: The master switch in the header turns all scheduled background jobs on or off. If disabled, tasks will only run when you manually click them on the Stalled Torrents or Maintenance pages.
  • Time & Unit: Each task has a number field and a unit dropdown (Hours or Minutes).
  • Disabling a Timer: If you set a task's timer to `0`, that specific task will be disabled from the background scheduler, but you can still run it manually.
Task Watchdog & Timeouts

Python threads cannot be forcibly killed. This section provides an advisory watchdog.

  • If a script hangs or takes longer than the configured timeout (in minutes), it writes a Timeout warning to the History page.
  • This is purely for monitoring the health of the scripts. It does not kill the task; the task will continue running in the background until it finishes naturally.
  • 0 = disabled (used for tasks like Missing Media Sync that routinely take 30+ minutes).

qbit-doctarr can send you emails for important events and regular summaries.

Email (SMTP)
  • Configure your SMTP server details in Settings. Use the "Test Email" button to verify it works.
  • Warnings are sent in a single cycle (e.g., every 15 minutes) to avoid spamming you. Once a warning is sent, it won't be sent again unless it resolves and then returns.
  • Muted Sources: You can silence specific warnings (like App Update Available) by unchecking them in the Settings page.
Periodic Digest
  • Instead of individual warnings, you can receive a summary digest (daily, weekly, or monthly).
  • You can choose which sections to include (Task Activity, Health Changes, Current Snapshot).

General & Security
  • Global Dry Run: Simulates all automated actions. No files are deleted, moved, or modified in your *arr apps. Use this to test the system safely.
  • Basic Auth: Protects the UI with a simple username and password. Warning: Do not use this over HTTP unless you are behind a reverse proxy providing HTTPS, or your password will be transmitted in plain text.
  • Storage & Logging: Control history retention, log levels, and whether to save logs to a file.
Missing Media Search
  • Respect Indexer Constraints: Turns "Polite Mode" on/off.
  • Batch Size: How many searches to trigger per run (per *arr or total).
  • Cooldown & Retries: How long to wait before searching an item again, and how many attempts before marking it as failed.
Tracker Thresholds
  • Metadata Timeout: How long a torrent can sit on "Downloading Metadata" before the Stalled Tracker fails it.
  • Slow/Dead Timeout: How long a Force-Started torrent can download at 0 B/s before it is failed.
  • Unmanaged Age: How old a stopped torrent must be before it is deleted if no *arr is tracking it.
  • Slow Speed: The speed threshold that defines a "dead" or "stalled" download.
  • Max Percentage: The Stalled Tracker will IGNORE any torrent that has downloaded more than this percentage.
